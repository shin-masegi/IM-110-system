# 監査: 調整・校正・係数保存 — 仕様書 vs 実装 の食い違い全件

> 作成: 2026-07-26。対象 = `mlss-calc-reference.md`（真実源）と 本体 `IM-110` / プローブ `IM-110_Probe` の実装。
> 目的: 場当たり的な修正を止め、**実装すべき全機能を一覧化してから作り直す**ための基礎資料。
> きっかけ: 実機で MLSS が 0 のまま変化せず、原因が「No.21-30 の係数がプローブ上で全0」だったこと。
> 仕様書 §355 は「modecf が『全0』になる状態は**通常存在しない**」と明記しており、実装がこれを守れていない。

---

## 0. 用語の整理（混同が事故の原因になっている）

仕様書には**別物として**定義されているのに、実装・過去の議論で同一視されてきた対が2組ある。

| | 出荷時（工場・ADBOAD/UART のみ） | 現場（ユーザ・校正モード） |
|---|---|---|
| **ゼロ** | 出荷時清水中オフセット = `zr_ship`（§191） | ゼロ校正 = `zr_field` を上書き（§192） |
| **3点** | **出荷時3点調整** → 基準2次式（Page4）を作る（§293, §326-336） | **3点校正** → 選択中 No.21-30 の独立2次式（§344）／ SP_A/B/C（§237） |

- 出荷時側は「基準カーブそのもの」を作る。現場側は「その上に乗る補正」を作る。
- 仕様書 §353-357: **出荷時3点調整の結果は No.21-30 全10スロットへコピー**され、それが未調整時の初期状態になる。
- **書き換え権限**（§392）: プローブ調整係数（ADSpan / LED duty / 出荷時2次式 / Ref温度補正）は **ADBOAD 操作または UART デバッグコマンドでのみ**書き換え可。通常のユーザ校正フローからは書き換えない。

## 1. 【重大】初期値が入らず 0 が真実源を破壊する経路

実機で実際に発生し、MLSS が 0 になった原因。

### A-1. 本体 live の相関式係数に初期値が無い

- `MLSS_Coef_ModeCF[EEP_CF_COUNT][7]` / `SS_Coef_ModeCF[][7]` は宣言のみ（`IM-110/Core/Src/IM_110.c:261-262`）。BSS なので **0 起動**。
- 仕様書 §526 は「本体 live 計算グローバルは起動時ハードコード INI（同値）で立ち上がるため、`RPG` 前でも測定は健全」と書くが、**相関式係数だけこれが成立していない**。
- 他のパラメータ（`MLSS_ZR = INI_MLSS_ZR` 等）は `IM_110.c:91` で初期値付き宣言されており、相関式係数だけが例外。

### A-2. 書戻しに非0ガードが無い

- `store_pack_from_globals()`（`IM_110.c:566-569`）は `MLSS_Coef_ModeCF[i]` を**無条件で**ストアへ詰める。
- 一方 `Apply_Coef_To_Live()`（`IM_110.c:1082`）には `modecf_is_set()` による非0ガードが**既にある**。読む側だけ守られ、書く側が無防備。
- 結果: プローブから読めていない状態（`BOOT:2` = RPG 失敗）で `AWC` を打つと、0 がプローブ flash へ書かれ **`RPF` の新品既定を破壊**する。
- 2026-07-25 に実装した**電源OFF一括書戻しも同じ経路**を通るため、`BOOT:2` で起動した日に電源を切るだけで係数が飛びうる。

### A-3. `ACRI`（相関式初期化）が staging を更新しない

- `Adj_ResetCorr()`（`IM_110.c:1831`）は `MLSS_Mode_CF[20..29]` と `SS_Mode_CF[20..29]` にコピーするだけで、**`MLSS_Coef_ModeCF[]` / `SS_Coef_ModeCF[]`（ストアへ pack される staging）を更新しない**。
- 結果: `ACRI` 実行後に `AWC` すると、live 表示は直っているのにプローブには 0 が書かれる。

## 2. 出荷時調整の系統が丸ごと未実装

### B-1. 出荷時3点調整のコマンドが存在しない

- 仕様書 §293（プローブ調整 第4ステップ）／§326-336（第2領域 出荷時3点校正係数）が定義する「基準2次式（Page4）を作る」機能に対応するコマンドが無い。
- 既存の `AMC`/`AMCF` は**現場校正**の実装:
  ```c
  int vi = (int)corr - EEP_CF_BASE_IDX;        // 選択中の相関式 No.
  if (vi < 0 || vi >= EEP_CF_COUNT) return -1; // No.1-20 選択時は失敗
  memcpy(MLSS_Coef_ModeCF[vi], coef, ...);     // 1スロットのみ更新
  ```
  （`IM_110.c:1924-1946`）
- Page4 の基準式（`MLSS_Mode_CF[0]` = `mlss_bc.c0/c1/c2`）を**書く経路がどこにも無い**。更新するのは `store_unpack_to_globals()`（プローブからの読込）だけ。
- ⇒ 出荷時3点調整を実施しても Page4 は初期値 21315 の1次直線のまま。

### B-2. 出荷時係数 → No.21-30 コピーが自動化されていない

- 仕様書 §354: 未調整（初期）状態 = 全10スロットに出荷時3点校正係数をコピー、k=1.00。
- 現状これを行うのは `ACRI` の手動実行のみ（かつ A-3 のバグ付き）。**出荷時3点調整の直後に自動でコピー**する処理が無い。

### B-3. ゼロ基準の「出荷時枠 / 現場枠」2枠が未配線

- ストアには `zr_ship` / `zr_field` の2枠がある（`probe_store.h:74-75`）。
- しかし `store_unpack_to_globals()` / `store_pack_from_globals()` は **`zr_field` しか触らない**（`IM_110.c:530, 561`）。`zr_ship` は `store_set_new_probe_defaults()` で書かれるだけで、以後読まれも書かれもしない。
- ⇒ 仕様書 §193「出荷時=初期値／校正=上書き／**初期化で出荷時へ復帰**」が成立しない。
- `AZC`（`Adj_CaptureZR`, `IM_110.c:1794`）は `MLSS_ZR`（＝ `zr_field` 相当）のみ更新。出荷時側を書く手段が無い。

### B-4. 「ゼロ初期化」機能が無い

- 仕様書 §501: 「**相関式初期化 / ゼロ初期化** = P4/P11 の出荷時ベース・**P3/P10 の MLSSZR_出荷時**を、対応する現場枠・No.21-30 スロットへコピー」。
- 相関式初期化（`ACRI`）はあるが、**ゼロ初期化に相当するコマンドが無い**。

## 3. 水深補正が保存されない

### E-1. `k_depth` がストアに同期されていない

- 本体 `Depth_k`（`IM_110.c:1282`）はグローバル変数。`AWD6`（`Depth_Calib_Span6m`, `IM_110.c:1314`）が `Depth_k = 6.0 / dp` を書く。
- ストアには `common.k_depth` の枠があるが、`store_pack_from_globals()` / `store_unpack_to_globals()` は **`common` を一切触らない**（係数ページのみ）。
- ⇒ **水深校正の結果は電源断で消える**。仕様書 §448「`k_depth` はプローブ側保存、ADBOAD/UART のみ書換」と食い違う。

### E-2. 既定値の単位が食い違う

- ストア既定 `STORE_DEF_KDEPTH = 1.0`（`probe_store.h:242`）。
- 本体 live 初期値 `Depth_k = 1.0f / 100.0f`（`IM_110.c:1282`）。
- 仕様書 §447 は「初期値 = 現行の固定 100hPa/m 相当（`k_depth = 1/100`）」。**ストア側の 1.0 が誤り**。同期を入れると水深が 100 倍になる。

## 4. TR（透視度）の枠が未分離

### C-1. Page14（TR No.21 校正後）が未使用

- 仕様書 §498: Page14 = 「TR No.21 ＋予備」＝ 累乗 a,b（校正後）。Page13 = 出荷時ベース。
- 実装は `store_unpack_to_globals()` / `store_pack_from_globals()` とも **Page13 (`s->tr`) のみ**を扱い、Page14 (`store_p14_t`) に触れない。
- ⇒ TR の「出荷時ベース」と「校正後」が同一枠に混在。`AMCP`（累乗フィット）が Page13 の `pow_a/pow_b` を直接上書きするため、出荷時値が失われる。

## 5. 係数の二重管理（統合ストア vs 本体EEPROM legacy）

### H-1. 同じ係数を2箇所に別形式で保存している

- 統合ストア（Page3-15）と、本体EEPROM の legacy 校正ページ（page19-60, 2page/相関式）が**並存**。
- `read_param_calibration()` / `write_param_calibration()`（`Eeprom.c:2975-3055`）は `ZR / FABS_SPAN / SP_A / SP_B / SP_C / 1A / 1B` の7 float を読み書きする。
- このうち `FABS_SPAN` / `1A` / `1B` は**旧モデルの遺物**で統合ストアに存在しない。`MLSS_FABS_SPAN` は仕様書 §225 で「廃止（式には未使用、初期 1.0 のまま残存）」とされている。
- 仕様書 §480: 「既存の本体EEPROM疎レイアウト(page19-60, 2page/相関式)は本配置に**置換**」＝ 統合ストアミラーへ一本化する方針。**未実施**。
- `Calib_SaveWriteback_Current()`（`IM_110.c:2295`）は両方へ書いている（`write_param_calibration` + `Probe_WriteBackCalibration`）。

## 6. SS の扱い

### D-1. 配列サイズと実体の不一致

- 仕様書 §400: 「SS / TR は相関式 No. が無い＝**No.21 の単一式のみ**」。
- 実装は `SS_Coef_ModeCF[EEP_CF_COUNT][7]`（10枠）を確保しているが、ストアは `ss_eq` 1枠のみ。unpack/pack も `[0]` のみ使用（`IM_110.c:551-552, 577`）。
- 実害は薄いが、`Adj_ResetCorr()` が `SS_Mode_CF[20..29]` 全部にコピーしている等、意図が読み取りにくい。

### D-2. ~~SS に k_No モデルが無い~~ → **食い違いではない（誤検出・取り下げ）**

- 仕様書 §344「No.21〜30: 傾き(ゲイン) k は **1.00 固定**（傾きは 2 次式係数に内包されるため追加ゲイン不要）」／§400「SS / TR は相関式 No. が無い＝**No.21 の単一式のみ**」。
- ⇒ **SS はゲイン 1.00 = MLSS の No.21 と同じ動作**が仕様。実装 `eval_modecf(SS_Mode_CF[SS_MODE], abss)`（k 乗算なし）は**仕様どおり正しい**。
- §383「SS も同構造」は「基準式＋ゲイン」という構造の話であり、SS に k_No 表が要るという意味ではない。

## 7. Page2（プローブ設定）— **配線不要で決定済み**

### F-1. ~~選択中相関式 No. などが保存されない~~ → **食い違いではない（決定済み）**

- **選択中相関式 No.・Meas_Mode・SetVal は本体側で保持する**という決定済み方針（§483「保存は『選択中 No.』のみ」）。
- 実装も本体 EEPROM の common ページで永続化されている（`write_param_common()` / `eep_read_calhis()` が `Meas_Mode` / `MLSS_MODE` / `SS_MODE` / `TR_MODE` / `*_Cal_SetVal_*` を読み書き, `Eeprom.c:1860-1873, 2904`）。
- ⇒ ストア Page2 は**プローブ側に配線しない**。枠は予備として残す。仕様書 §515 の「非配線・中立」はこの決定の記述。

## 9. 実装タスク一覧（この監査から導かれる作り直しの範囲）

依存順。**1 を入れないと他をやっても同じ事故が再発する。**

### 1. 破壊防止（最優先・小さい）
- [ ] A-1: 本体 live `MLSS_Coef_ModeCF` / `SS_Coef_ModeCF` に初期値を入れる（`STORE_DEF_SLOPE` を単一ソースに）
- [ ] A-2: `store_pack_from_globals()` に非0ガードを入れる（全0の係数ページは既存ストア値を残す）
- [ ] A-3: `Adj_ResetCorr()` が staging（`*_Coef_ModeCF`）も更新するよう修正

### 2. 出荷時系統の新設
- [ ] B-1: 出荷時3点調整コマンドを新設（フィット結果を **Page4 基準式**へ書く。No. 非依存）
- [ ] B-2: 出荷時3点調整の直後に **No.21-30 全10スロットへコピー**（k=1.00）
- [ ] B-3: `zr_ship` / `zr_field` の2枠を unpack/pack に配線。出荷時ゼロを書くコマンドを新設
- [ ] B-4: ゼロ初期化コマンドを新設（`zr_field ← zr_ship`）

### 3. 保存漏れの修正
- [ ] E-1/E-2: `k_depth` を store `common` に同期。ストア既定を `1/100` に訂正
- [ ] C-1: TR の Page14（校正後 a,b）を配線し、出荷時ベース（Page13）と分離

### 4. 二重管理の解消（決定済み・§480）
- [ ] H-1: 本体EEPROM legacy 校正ページ（page19-60, 2page/相関式）を統合ストアミラーへ置換。
      旧モデルの遺物 `FABS_SPAN` / `1A` / `1B` も併せて整理

### 5. 仕様書の修正（コードが正しい箇所）
- [ ] G-1〜G-6 を実態に合わせて更新

### 対象外（決定済み・実装も仕様どおり）
- D-2: SS のゲインは 1.00 固定（MLSS No.21 と同じ動作）＝ 現行実装が正しい
- F-1: 選択中 No.・Meas_Mode・SetVal は**本体側で保持**する決定。ストア Page2 は配線しない

## 10. 現在の実機状態（この監査の起点）

```
AMIR,BOOT:0,L2:1,CONN:1
AMIR,MIR:1,ID:FFFFFFFF,UPD:20260726
AMIR,PRB:1,ID:FFFFFFFF,UPD:20260726
AMIR,LIVE,MLSS_ZR:1868.67,C1:21315.00,SPB:1.0000,SV1:8000.0
AMV,0,J:603.08,R:1726.50,ABS:0.49116,F:0.0000,V:0.000   ← ABS は出るが F=0
AST,mode:0,eq:29                                        ← No.30 選択

プローブ統合ストアの実測デコード:

```

Page5 (No.21/22)          q0=[0,0,0]  q1=[0,0,0]            ← 全0

- No.21-30 だけが 0 になったのは、`MLSS_Coef_ModeCF` が本体 live で 0 のまま `AWC` が書き戻したため（A-1 + A-2）。
