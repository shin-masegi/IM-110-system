# FW バージョン採番ポリシー（feedback）

> 出所: ユーザー指示 2026-08-05「一気に Ver. をあげすぎなので、次回からはプッシュのタイミングで 1 つあげるように」。
> 背景: 2026-08-05 に本体 FW を 1 日で 0.37→0.38→0.39→0.40 と 4 回採番した（修正ごとに +1 していた）。

**ルール: FW バージョン（本体 `FW_VER1` / プローブ `P_VER`）は push の節目で 1 つだけ上げる。**

- 日中の修正・実機書込の反復では**採番しない**。同じ「次バージョン」の下に変更を積む。
- Changelog エントリも push 単位の 1 バージョンにまとめる（修正ごとに新エントリを切らない。
  同一バージョン内の項目として追記していく）。
- push の節目 = CLAUDE.md §3.6 の「節目のタイミング」（1 日の区切り指示・明示的な push 指示・
  リリース/プロトコルバージョン切替）。
- 実機に書き込む中間ビルドのバージョン表示が最終 push 版と同じになるのは許容
  （従来も「採番前ビルド書込 → 次回書込で表示一致」の運用実績あり）。

**Why:** 修正ごとの採番はバージョン番号を浪費し、「実機の表示 Ver」と「リポの HEAD」の対応が
1 日の中で何度もずれる。push 単位なら Ver ↔ コミットが 1:1 で追跡できる。

**How to apply:** 修正時は Changelog の最新（未 push）エントリに追記し、`FW_VER1`/`P_VER` は
その push サイクルで最初の変更時に 1 回だけ +1 する。既に採番済みの 0.37〜0.40 / 0.27 はそのまま。
