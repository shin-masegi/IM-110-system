通信信頼性の切り分けとは別系統で見つかった不具合を、後で潰すために記録する。

## KI-1: 電源OFF時の「保管方法」ガイドが毎回表示される (本来は1日1回)

- **発見**: 2026-07-19。ユーザー報告「電源OFFで保管方法表示が毎回でる。1日1回だけのはず」。
- **系統**: 本体 UI/EEPROM 永続化。**統合ストア/通信の件とも、私(Claude)の切り分け変更とも無関係**
  (577a769 起動分離リファクタも該当領域=main.c init 部を未変更、と git 確認済み)。

### 確定した直接原因 (openocd 実機読取, 電源断なし)
- `guide_disp_flag[0..4]` が起動時 **全部 0**(=表示する)。
- `LastDate` = 19/12/11 = RTC 現在日と一致(検証機 RTC は 2019/12/11)。
- フラグは起動時 EEPROM 復元のみ(他に毎起動 0 化する箇所なし)。
  → **「表示済(=2)」が EEPROM に永続化されていない**ため毎起動 0 → 毎回表示。

### 構造的弱点 (初期コミット由来・今回の regression ではない)
- `main.c:368-370` で `LastDate=今日` を、`main.c:400` の `day_disp_reset()`
  (`今日 != LastDate` で `guide_disp_flag` 2→0)**より前**に上書き。
  よって起動時の日次リセットは常に不発。1日1回はフラグ永続化のみに依存していた。

### 永続化が崩れた場所の候補 (未確定・Phase 2 で切り分け)
1. 電源OFF `shutt_down()`(mainSub.c:553)で flag=2 セット + `Req_SetupData_Write=1` するが、
   保存 `eep_write_setting()`(消費は mainSub.c:925)が電源断前に走っていない可能性。
   - guide 表示経路は2つ: `mainSub.c:567`(shutt_down) と `Normal.c:3589`。
     Normal.c:3780-3781 は flag=1 + Req_Write をセット。どちらが実際に保存まで到達するか要確認。
2. 統合ストア対応(e933955 / 57171eb)で EEPROM SetupData の offset がずれ、
   `guide_disp_flag`/`LastDate` の読み書き位置が不一致になった可能性(Eeprom.c:726-729 / 1386-1389)。

### デバッグ手段
- 走行中 RAM 読取(電源断なし)= openocd。手順は memory `im-110-debugger-live-read`。
  アドレス: `guide_disp_flag=0x20003c74`(5B), `LastDate=0x20003c64`(3B)。
- UART デバッグダンプ: LinkSerial.c:1074(guide_disp_flag) / 1097(LastDate)。
- EEPROM 実内容の該当 offset を読めば候補1 vs 2 を確定できる。

## KI-2: 本体EEPROMミラーが一度も有効になっていなかった（2026-07-25 発見・**修正済**）

- **発見**: 2026-07-25。T1 の起動時3層ロードを実機検証するため `AMIR`（統合ストア状態ダンプ）を追加したところ、
  `mirror_save()` 直後にもかかわらず `MIR:0`（ミラー無効）が返った。
- **直接原因**: **ページ末尾 XOR のシード値が本体EEPROM層と統合ストア層で不一致**。
  - `eep_write_page()`（`Eeprom.c`）: `cs = 0xFF` から byte[0..30] を XOR し、**byte31 を上書き**して書き込む
  - `store_page_xor()`（`probe_store.h`）: `x = 0` から byte[0..30] を XOR
  - → EEPROM へ書いた瞬間 byte31 が `store_page_xor ^ 0xFF` になり、読み戻すと `store_verify_pages()` が
    全16ページで不一致 → `store_valid()` が必ず 0。
- **影響（修正前）**: ドキュメント上「実装済み」だったミラー機能が実質全滅していた。
  - 層2（ミラー→live 起動ロード）が常に不発 → **プローブ断時のフォールバックが成立しない**
  - プローブID／最終更新日の調停が常に「ミラー無効」判定 → §A-2 の4分岐が実質1本道
  - 電源OFF一括書戻しの差分判定が常に不成立 → **毎回無条件に16ページ書戻し**（プローブ flash の無駄な消耗）
  - 既存の `Probe_SyncStore()` も毎回「ミラー無効」経路を通っていた（magic は読めるため memset は回避されており実害は出ていなかった）
- **修正**: `mirror_load()` の末尾で `store_seal_pages()` を呼び、byte31 を統合ストアの正準形へ復元する
  （`IM-110/Core/Src/IM_110.c`）。byte31 は保存媒体それぞれが持つ冗長バイトであり、EEPROM 側の XOR は
  `eep_read_page()` がリトライ付きで検証済み、ストア全体 checksum は byte31 を除外して計算されるため、
  整合性チェックはどちらも甘くならない。
- **実機確認**: 修正後の起動で `MIR:1`、電源OFF書戻し→再投入で `L2:1` と係数の保持を確認。
- **教訓**: 「同一バイト配置でミラーする」設計で、**各媒体が独自の冗長バイトを同じオフセットに持つ**場合は、
  シード・アルゴリズムまで一致させるか、読出時に正準形へ復元する層を必ず挟むこと。

## KI-3: 電源OFF時に約2秒待たされる（2026-08-02 記録）

- **報告**: 2026-08-02 ユーザー報告。電源OFF操作から実際に切れるまで約2秒かかる。
- **原因（機構としては仕様どおり）**: §A-2 の電源OFF一括書戻し。シャットダウン窓で
  `Probe_SyncStore()` = MS停止 → `WPG`×23ページ → `WSC`(プローブflash確定) → 本体EEPROMミラー保存
  を実行する。9600bps で WPG 25行 ≈1.8KB ≈**1.9秒** + WSC の flash 消去/書込 + ミラー25ページ書込で
  合計約2秒（転送量からの計算値。実測での内訳は未取得）。
- **対策候補（未着手）**:
  1. **差分書戻し**: 2026-08-02 以降、調整・校正は確定のたびに即 SyncStore しているため、
     OFF 時点でプローブと本体RAMが一致しているケースが大半のはず。dirty フラグまたは
     ミラーとの比較で**変更ページのみ WPG**（protocol §3.2.6 は変更ページのみの送出を許容済み）
     すれば、通常は Page0(日付) 程度 → 数百 ms に短縮できる。
  2. ボーレート引き上げ（両側同時変更 + protocol §1.1 改訂。38400 なら転送 1/4）。

## KI-4: ADBOAD 起動が初回に約2秒待たされる（2026-08-02 記録）

- **報告**: 2026-08-02 ユーザー報告。ADBOAD（基板調整モード）の初画面表示までに約2秒かかる。
- **原因（仕様どおりの副作用）**: 2026-08-02 の仕様確定「ADBOAD こそプローブの全係数を厳密に
  読み込む」により、ADBOAD でも起動時に VR 疎通 + `RPG` 一括読出し（層3）を実行するように
  変更した（起動マージン300ms + VR + RPG ≈1.9秒 @9600bps）。測定モードには約2.5秒の起動画面が
  あり読み込みが裏に隠れるが、**ADBOAD には起動画面がないため素通しで待ちに見える**。
- **対策候補（未着手）**:
  1. ADBOAD 起動時に「読み込み中」表示を出す（体感の改善のみ）。
  2. **差分読み込み**: まず `RPG,0`（Page0 のみ）で checksum/最終更新日を取得し、ミラーと一致
     なら残り22ページをスキップ（既存の単一ページ読出し `RPG,<N>` で実装可能）。一致時は
     数百 ms に短縮。KI-3 の差分書戻しと対で入れるのが筋が良い。
  3. ボーレート引き上げ（KI-3 と共通）。
